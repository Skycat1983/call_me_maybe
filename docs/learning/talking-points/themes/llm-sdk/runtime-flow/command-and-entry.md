## Stage 0: Before execution

### Files that already exist

| File | Role |
|---|---|
| `Makefile` | Stable human-facing commands and `/tmp` environment variables |
| `pyproject.toml` | Human-authored dependency intent and uv configuration |
| `uv.lock` | uv-generated resolved dependency graph |
| `experiments/inspect_sdk.py` | Locally authored diagnostic coordinator |
| `llm_sdk/llm_sdk/__init__.py` | Supplied SDK wrapper being investigated |

### Persistent versus disposable state

```text
Repository source and lockfiles       persistent project state
/tmp/call-me-maybe-venv               reproducible installed environment
/tmp/call-me-maybe-uv-cache           disposable package cache
/tmp/call-me-maybe-huggingface        disposable model/tokenizer cache
model and tensors in process memory   exist only while the Python run lives
```

If `/tmp` has been cleared, `make install` recreates the Python environment.
Model construction later recreates missing Hugging Face artifacts.

## Stage 1: Make chooses the recipe

The controlled CPU command is:

```bash
make inspect-sdk-cpu
```

Make finds this target:

```make
inspect-sdk-cpu:
	uv run python experiments/inspect_sdk.py --device cpu
```

Before the recipe starts, exported Make variables tell child processes where
to store the environment and caches.

### What Make holds

Make holds text values, not Python objects:

| Name | Text value | Purpose |
|---|---|---|
| `UV_PROJECT_ENVIRONMENT` | `/tmp/call-me-maybe-venv` | Virtual-environment location |
| `UV_CACHE_DIR` | `/tmp/call-me-maybe-uv-cache` | uv download/build cache |
| `HF_HOME` | `/tmp/call-me-maybe-huggingface` | model and tokenizer cache root |
| `UV_LINK_MODE` | `copy` | package installation strategy from cache |

### What `uv run` does here

uv checks that the environment matches the project declaration and lock, then
starts the requested Python executable inside that environment. uv is not the
model and Make is not the package resolver; each delegates to the next layer.

## Stage 2: Python loads the probe module

Python executes the file from top to bottom.

### Module docstring

The first triple-quoted string becomes the module's `__doc__` value. The
argument parser later reuses that text in `--help` output.

### Imports

| Imported name | Kind | What the probe uses it for |
|---|---|---|
| `ArgumentParser` | class | Parse `--device` |
| `Callable` | type form | Describe a zero-argument path getter returning `str` |
| `nlargest` | function | Select the highest-scoring logit indices |
| `Path` | class | Check returned files and sizes |
| `perf_counter` | function | Measure elapsed duration |
| `cast` | typing helper | Narrow the device return type for Mypy without changing its runtime value |
| `Small_LLM_Model` | supplied class | Access tokenizer and model through public methods |

Importing `Small_LLM_Model` loads and defines the SDK class. It does not yet
construct a Qwen model. Construction occurs only when the class is called in
`main()`.

### Constants

| Name | Type | Value | Meaning |
|---|---|---|---|
| `PROMPT` | `str` | `"What is the sum of 2 and 3?"` | Fixed diagnostic input |
| `TOP_CANDIDATE_COUNT` | `int` | `10` | Number of logits candidates to report |

These were written locally for the experiment. They were not supplied or
generated by Qwen.

### Function definitions

When Python reaches each `def`, it creates a function object and binds it to a
name. The function body does not run yet.

This distinction matters:

```text
def main(): ...       defines main
main()                executes main
```

## Stage 3: The module guard enters `main()`

At the bottom:

```python
if __name__ == "__main__":
    main()
```

Because Python is executing this file directly, `__name__` equals
`"__main__"`, so `main()` is called. If a test imported this module, its
functions would become available without automatically loading Qwen.

## Stage 4: Parse the device argument

`main()` first executes:

```python
requested_device = parse_device_argument()
```

### Inside `parse_device_argument()`

```python
parser = ArgumentParser(description=__doc__)
```

`parser` holds an `ArgumentParser` object. That object holds rules describing
which command-line inputs are allowed; it does not hold the selected device
until parsing happens.

The call:

```python
parser.add_argument(
    "--device",
    choices=("cpu", "cuda", "mps"),
    help="Pass an explicit device to Small_LLM_Model.",
)
```

registers one optional rule:

- option spelling: `--device`;
- permitted strings: `cpu`, `cuda`, `mps`;
- help-screen explanation.

Then:

```python
return cast(str | None, parser.parse_args().device)
```

performs these operations:

1. read the process arguments;
2. validate `--device cpu`;
3. create an argparse namespace object;
4. read its `.device` attribute;
5. return the string `"cpu"`.

Mypy sees the dynamically created namespace attribute as `Any`.
`cast(str | None, ...)` records the type established by the parser rules for
static analysis. It performs no runtime conversion or validation.

### Variable after return

```text
requested_device
type: str | None
controlled CPU run: "cpu"
default run: None
owner after return: main()
```

### Why the device argument exists

It is not a subject requirement. It is a diagnostic control and currently a
workaround. Explicit CPU avoids the observed automatic CUDA/device-map branch
that required `accelerate`.

Supplying a device can:

- reproduce behavior on known hardware;
- isolate a hardware-specific failure;
- compare speed and compatibility;
- force a portable CPU path;
- prevent an automatic choice from changing the experiment.

Hardware paths are worth comparing because they can choose different loading
branches, dtypes, dependencies, memory strategies, and kernels. Changing only
the device argument makes the comparison easier to interpret.

## Stage 5: Print the first report heading

```python
print_heading("Model construction")
```

The argument `title` temporarily holds the string `"Model construction"`.
The function returns `None`; its effect is terminal output.

`print(f"\n## {title}")` is an f-string. Python substitutes the current value
of `title` before passing the final string to `print()`.
